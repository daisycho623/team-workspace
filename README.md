# CX 업무 관리 대시보드

Google Sheets `CX` 탭을 읽는 반응형 HTML/CSS/JS 대시보드입니다.

## 로컬 실행

Node.js가 설치된 환경에서 `npm start`를 실행하고 http://127.0.0.1:3000 을 엽니다. 추가 패키지 설치는 필요하지 않습니다. 포트는 `PORT` 환경변수로 바꿀 수 있습니다.

## 서버 저장소

`npm run import:cx`로 실제 CX 탭을 서버의 `data/cx.json`에 저장합니다. 원본 CSV의 전체 열과 값, 원본 행 번호, 출처와 가져온 시각을 보존합니다. 화면의 열은 시트 헤더로 매핑하며 없는 업무 종료 시간은 빈칸으로 둡니다.

프로젝트 서버는 `/api/tasks`로 저장된 업무와 작업자를 제공합니다. 로컬 화면은 이 데이터를 우선 읽으므로 서버 재시작 후에도 유지되며 조회 시 Google 연결이 필요하지 않습니다. 새로고침은 저장소를 다시 읽습니다. 시트의 최신 내용을 다시 저장하려면 `npm run import:cx`를 실행하세요. 기존 파일은 `data/backups/`에 백업되며 빈 시트로 기존 업무를 덮어쓰지 않습니다. `data/`는 Git에서 제외됩니다.

정적 호스팅처럼 `/api/tasks`가 없는 환경에서는 기존 Google Sheets 조회를 사용합니다. 시트 조회는 Google Visualization의 JSONP 응답을 사용하므로 로컬 출처에서도 읽을 수 있습니다. 가져오려는 시트는 로그인 없이 조회할 수 있도록 공유되어 있어야 합니다.

- 업무: `app.js`의 `ID`에 지정된 스프레드시트의 `CX` 탭
- 작업자: `config.js`에 지정된 Apps Script의 `getWorkers` API. 연결 실패 시 같은 스프레드시트의 `작업자` 탭 A열을 읽습니다(첫 행의 `작업자` 제목 제외).
- 새로고침 버튼: 서버 저장소의 업무·작업자를 다시 조회합니다. 저장소가 없는 정적 환경에서는 시트를 조회합니다.
- 빈 시트: 연결 성공으로 처리하며 `등록된 업무가 없습니다`를 표시합니다.
- 조회 실패: 연결 오류를 표시하고 이미 화면에 있는 업무는 유지합니다.

기존 업무의 로컬 수정값은 화면에 계속 적용됩니다. 서버 원본을 다시 확인하려면 `수정 초기화`를 누르세요. 저장소를 새로 가져온 경우 이전 자료의 로컬 수정값은 새 자료에 적용하지 않습니다. 새 업무 저장은 기존 Apps Script `appendTask` API로 시트에 저장합니다. 이를 서버 저장소에 반영하려면 다시 가져오기를 실행해야 합니다. 서버 저장소는 가져온 시점의 사본이며 자동 양방향 동기화는 하지 않습니다.
